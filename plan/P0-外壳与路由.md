# P0 外壳与路由

依赖：无。可直接在现有代码上开工，不改数据库。

## 目标

把七项导航换成五项，把基于 hash 的视图切换换成可直链的路由树，把前后端契约变成生成产物。P0 结束时功能与现在等价，但页面入口、URL 与接口类型已经按新架构就位。

## 进入条件

- 现有后端 229 个用例通过，前端 19 个用例通过，`npm run build` 无错。
- 确认旧链接清单，避免改路由后回不去。旧入口是 `#/board`、`#/split`、`#/locator`、`#/assets`、`#/library`、`#/search`、`#/settings`。

## 范围

| 做 | 不做 |
| --- | --- |
| 引入 TanStack Router，建立路由树 | 不改任何后端业务逻辑 |
| 侧栏改五项：资产库、提示词工程、审片台、制作、设置 | 不建新表，不动 `db.py` |
| 旧 hash 链接重定向 | 不做资产索引（P1） |
| `openapi.json` 生成与 `openapi-fetch` 客户端 | 不做播放器与编辑器 |
| Vitest + Testing Library 接入 | 不迁移旧 `node:test` 用例 |
| CORS 增加 Tauri 来源 | 不处理 sidecar 启动握手（P8） |

## 步骤

1. 安装依赖：`@tanstack/react-router`、`openapi-fetch`；开发依赖 `openapi-typescript`、`vitest`、`jsdom`、`@testing-library/react`、`@testing-library/jest-dom`。版本在开工时锁定，写进 `web/package.json`。

2. 建 `web/src/app/router.tsx`，用代码式路由，不启用文件路由插件，避免改 `vite.config.ts` 的构建链。路由树：

| 路径 | 组件 | P0 的临时内容 |
| --- | --- | --- |
| `/` | 重定向 | 跳到 `/assets` |
| `/assets` | `AssetLibrary` | 现有页面，P1 替换 |
| `/assets/$assetId` | 抽屉态 | 用 search 参数 `?asset=` 代替，P1 再决定是否独立路由 |
| `/prompts` | 段列表占位 | 先渲染 `SplitPanel`，P3 替换 |
| `/prompts/$seg` | 工作台占位 | 同上，带上 `seg` 参数 |
| `/review` | `GachaBoard` | 现有卡片墙，P6 替换 |
| `/review/$seg/$block` | 审片详情占位 | P0 跳到 `/review?seg=&block=` |
| `/produce` | 占位页 | 显示「任务台建设中」，P7 替换 |
| `/settings` | `SettingsPage` | 现有页面，保留 |

3. `main.tsx` 保留 `QueryClientProvider` 与 `Toaster`，把 `<App />` 换成 `<RouterProvider router={router} />`。

4. `App.tsx` 改成根布局 `RootLayout`：左侧 `Rail`，上方 `TaskBar`，右侧 `<Outlet />`。删掉 hash 监听、`viewFromHash`、`view` 写回 URL 三段逻辑。

5. 改 `web/src/components/Rail.tsx`：七项变五项，图标沿用 `lucide-react`。工作区切换与底部健康灯位置不变。当前项由 `useRouterState` 的路径判断，不用 store。

6. 旧链接重定向。在根路由 `beforeLoad` 里检查 `location.hash`，按下表跳到新地址：

| 旧 | 新 |
| --- | --- |
| `#/board` | `/review` |
| `#/split` | `/prompts` |
| `#/locator` | `/prompts` |
| `#/assets` | `/assets` |
| `#/library` | `/assets?collection=novel` |
| `#/search` | `/search` |
| `#/settings` | `/settings` |

跳转用 `redirect`，并在新地址上清掉 hash。

7. 清 `web/src/store/useApp.ts` 的 `View` 与 `setView`。筛选条件搬到路由 search 参数（`status`、`seg`、`q`），P0 先保留 `filter` 与 `seg` 两个字段给旧页面用，P1 之后再删。

8. 生成接口类型。新增 `backend/tools/dump_openapi.py`：

```python
from main import app
import json, sys
json.dump(app.openapi(), open(sys.argv[1], "w", encoding="utf-8"), ensure_ascii=False, indent=2)
```

新增 `web/scripts/gen-api.mjs`：先调后端 venv 的 python 生成 `src/lib/openapi.json`，再调 `openapi-typescript` 输出 `src/lib/api-schema.d.ts`。`package.json` 加 `"gen:api": "node scripts/gen-api.mjs"`。

9. 新增 `web/src/lib/client.ts`，创建 `openapi-fetch` 实例，`baseUrl` 取 `import.meta.env.VITE_API_BASE ?? "http://127.0.0.1:8000"`。旧 `lib/api.ts` 暂时保留，P1 起新代码只用 `client`。

10. CORS 增加 Tauri 来源 `tauri://localhost`、`http://tauri.localhost`，保留现有开发来源。这一步先加，避免 P8 才发现桌面端请求被拦。

11. 加根级错误边界与 404 页。路由 `errorComponent` 显示错误摘要与「返回资产库」，`notFoundComponent` 显示原路径。

12. `package.json` 增加 `"test:ui": "vitest run"`，新增 `vitest.config.ts`（`environment: "jsdom"`，`setupFiles` 挂 jest-dom）。`npm test` 仍跑 `node:test` 的 19 个用例，两者并存。

## 风险与回退

路由重写会打断用户收藏的旧链接，重定向表必须覆盖全部七个入口。若 TanStack Router 与 React 19 的当前版本出现类型冲突，先锁定可用组合，不启用文件路由插件。

回退方式：保留 `App.tsx` 与旧 `Rail` 的提交，路由问题无法当天解决时切回 hash 版本，P0 的接口生成与测试接入可以单独保留。
