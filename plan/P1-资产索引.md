# P1 资产索引

依赖：P0。这是新数据层的第一段，旧功能继续用 `db.py`，两者写不同表。

## 目标

给工作区里的每个文件建立一条记录，能按角色、主体、类型、关键词筛选，能显示文件被哪些提示词或分镜提到。索引在后台跑，窗口先可用；磁盘变化后自动补扫。

## 进入条件

- P0 的五项导航与接口类型生成可用。
- 确认 `config.folder_names_for()` 与 `FOLDER_KEYS` 的现有语义，目录角色不重新发明。
- 确认 `db.py` 的库位置是 `<工作区>/.gachabench/cards.db`，P1 沿用。

## 范围

| 做 | 不做 |
| --- | --- |
| SQLAlchemy 引擎、Alembic baseline | 不重写旧 `cards`、`jobs` 等表的访问代码 |
| `assets`、`asset_meta`、`asset_ref`、`collections` 四组表 | 不做改名与删除（P2） |
| 全工作区扫描、增量补扫、文件监听 | 不做提示词解析（P3） |
| FTS5 搜索与分页接口 | 不做视频探针（P6 补） |
| 缩略图与媒体流 | 不做社区集合的编辑（P2 补） |
| 资产页只读列表与详情 | 不做写操作与拖放 |

## 步骤

1. 加依赖：`sqlalchemy>=2.0`、`alembic`、`watchfiles`、`pillow`、`pytest`。写进 `backend/pyproject.toml`，锁版本。

2. 建 `backend/modules/platform/db.py`：

- 按工作区根目录缓存 engine，`create_engine("sqlite:///<root>/.gachabench/cards.db")`；
- 连接事件里设 `journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`；
- `Session` 用 `sessionmaker(bind=engine, expire_on_commit=False)`；
- 暴露 `session_scope(root)` 上下文管理器。

3. 建 `backend/migrations/` 与 `alembic.ini`。第一版 baseline 必须包含旧 `SCHEMA` 的全部表（`cards`、`split_plans`、`jobs`、`assets`、`books`、`chapters`），再补 P1 新表。对已有库执行 `alembic stamp head`，不重建、不搬数据。

4. 建 `backend/modules/assets/models.py`：

| 表 | 字段 |
| --- | --- |
| `assets` | id、path 唯一、role、subject、category、ext、size、mtime、sha256、hash_status、media_kind、width、height、duration、fps、status、missing_at、created_at、updated_at |
| `asset_meta` | asset_id 主键、tags_json、aliases_json、note、subject_override |
| `asset_ref` | id、asset_id、file_path、line、col、kind、segment |
| `collections` | id、name、kind、filter_json、builtin |
| `collection_items` | collection_id、asset_id |
| `scan_runs` | id、started_at、finished_at、status、stats_json |

`assets.id` 用 ULID 字符串，改名不改 id。`status` 取 `active`、`missing`、`trashed`。

5. 给 `op_log` 加 `seq`、`prev_hash`、`op_hash`、`actor` 四列，全部可空。P1 写入时 `actor` 填 `local`，其余留空到 v2。

6. 建 `backend/modules/assets/indexer.py`：

- 从工作区根递归，跳过 `.gachabench`、`.git`、`node_modules`、`__pycache__`、`.tmp-*`，不跟随符号链接；
- 每个文件算相对 POSIX 路径、大小、mtime；
- 角色映射：一级目录名与 `config` 的目录角色匹配则取该角色，其余为 `other`；
- 主体：文件名去掉扩展名后按 `[_\s]+` 切分，第一段；切不出则留空；
- 类别：按扩展名分 `image`、`video`、`audio`、`text`、`archive`、`other`，素材目录内再按 `image/video` 细分；
- 哈希：1 MiB 分块读，算 `sha256`；超过 2GB 只记 `size+mtime`，`hash_status="quick"`；
- 以 path 为键 upsert，已有记录保留 id 与 `asset_meta`；磁盘上没有的标 `missing`，不直接删。

7. 增量判断：扫描前用 `os.scandir` 建目录树，目录 mtime 未变且该目录下已有记录时跳过读取条目。全量重扫由 `force=true` 触发。

8. 缩略图：图片用 Pillow 生成 320px 宽 WebP，落在 `.gachabench/thumbs/<哈希前两位>/<哈希>.webp`。视频缩略图 P1 不生成，列表用类型占位图。

9. FTS5：建虚拟表 `asset_fts(asset_id UNINDEXED, name, subject, tags, aliases)`，`tokenize="trigram"`，支持中文子串。写入由应用层在 upsert 时同步，重扫后整表重建。SQLite 不支持 trigram 时退回 `LIKE '%q%'`，启动时探测一次并记日志。

10. 扫描任务：进程内单飞任务，`scan_runs` 记状态；每 200 个文件通过 SSE 发一次进度。启动时若库为空或 `schema` 版本落后，自动触发一次全量扫描。

11. 文件监听：`watchfiles.awatch` 作为后台任务，事件按 300ms 去抖合并，忽略 `.gachabench` 与临时文件。收到变化后触发增量扫描，扫描期间的新事件只标记「需要再扫」。

12. 接口：

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/assets` | 参数 `role`、`category`、`collection`、`q`、`cursor`、`limit` |
| `GET /api/assets/{id}` | 记录、标签、引用列表（P2 才有数据） |
| `PATCH /api/assets/{id}` | 只改 `asset_meta`：标签、别名、备注、主体覆盖 |
| `GET /api/assets/collections` | 内置集合与数量 |
| `POST /api/assets/scan` | `{force: bool}`，返回任务 id |
| `GET /api/assets/scan/{id}` | 任务状态与统计 |
| `GET /api/media?path=` | 带 Range 的文件流，路径必须落在工作区内 |
| `GET /api/thumb?path=` | 缩略图，命中缓存直接返回 |
| `GET /api/events` | SSE，事件 `index.progress`、`file.changed` |

13. 前端 `/assets`：

- 左栏角色树（资产、分镜、提示词、成片、草稿、其他）与集合；
- 中栏虚拟网格，缩略图懒加载，多选只做选中态；
- 右栏详情：路径、大小、哈希、主体、类别、标签、引用；
- 顶部搜索框接 `q`，防抖 250ms，写进 URL；
- 底部细进度条显示扫描进度，`file.changed` 只刷新当前视图。

## 数据变更

新建五张表与一张 FTS 虚拟表；`op_log` 加四列。旧表不动。迁移对已有库执行 `stamp`，新库直接 `upgrade head`。

## 测试与验收

| 用例 | 判定 |
| --- | --- |
| 临时工作区建 500 个文件 | 记录数与文件数一致，重复扫描不新增 |
| 中文文件名搜索 | 输入文件名中间两个字能命中 |
| 目录角色识别 | `素材`、`资产`、`assets` 三种命名都映射到 `asset` |
| 跳过目录 | `.gachabench` 与 `.git` 内的文件不入库 |
| 删除文件后重扫 | 记录标 `missing`，不消失 |
| 路径穿越 | `GET /api/media?path=../../Windows/win.ini` 返回 400 |
| 哈希一致 | 同一文件两次索引 `sha256` 相同 |
| 首扫性能 | 1000 个文件在 30s 内完成（开发机实测，超时先看磁盘而不是改目标） |
| 二次扫描 | 无变化时在 2s 内结束 |

## 风险与回退

全量扫描可能拖慢低配机器，限制单次读取并发为 2，写入按 500 条一批提交。SQLite 的 trigram 分词依赖版本，启动探测失败时搜索退回 `LIKE`，功能不缺失只是变慢。

回退方式：新表独立，旧功能不依赖它们。停用 P1 只需撤掉新路由与扫描任务，旧页面照常打开。
