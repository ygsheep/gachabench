# P5 第一刀：规则诊断与可应用补丁（无模型）

依赖：P3 中间层与渲染、P5 原计划的 patch 结构。

## 为什么先做这一块

P5 原计划是「接一个外部模型，产 patch」。但用户真正卡住的不是「没人给初稿」——
初稿已经有确定性渲染器了；卡住的是**写完之后没人挑错**：正文里手滑写了时长、
把文件名贴进正文、独白忘了标无口型、素材表列了却没用上。这些不需要模型，
用字符串判断就能查，而且查得比模型准、比模型快、不花钱。

所以这一刀先把「规则诊断 + 可机械修的补丁」做实，模型那一半留到配好 Key 再上。
Provider 默认关闭，不配也能用全部现有功能——这条边界没变。

## 规则表

`backend/modules/prompts/checks.py`，只读文本 + 可选的中间层：

| 代码 | 级别 | 查什么 | 可自动修 |
| --- | --- | --- | --- |
| `MISSING_SECTION` | error | 三节（前缀/正文/尾部）缺哪节 | 否 |
| `MISSING_TAG` | warn | 十个小标题（【风格】…【参考】）缺哪个 | 否 |
| `BODY_HAS_DURATION` | warn | 正文镜头行里写了时长 | 是，删掉那段括号 |
| `REAL_FILENAME_IN_TEXT` | error | 正文/前缀里出现真实文件名 | 是（能对上素材表时换成占位） |
| `UNUSED_MATERIAL` | warn | 素材表列了占位，全文没引用 | 否 |
| `MISSING_MATERIAL_ROW` | error | 正文用了占位，素材表没有 | 否 |
| `SHOT_COUNT_MISMATCH` | error | 正文镜数与分镜表不一致 | 否 |
| `DIALOGUE_NOT_VERBATIM` | error | 分镜表台词在提示词里找不到原文 | 否 |
| `MONOLOGUE_NO_LIP` | warn | 内心独白没标无口型 | 是，行尾补标注 |
| `MISSING_SOUND_RULE` | warn | 缺「无BGM / 无字幕 / 无水印」 | 否 |
| `FEW_CONSTRAINTS` | info | 防崩约束少于 8 条 | 否 |
| `MISSING_CARRY` | info | 抬头没写承接 | 否 |

实现上的两个取舍：

- **文件名匹配以素材表为准**，不靠正则猜。文件名可以带空格和全角括号（`45云天娇睡衣 羽.png`），
  正则很容易把「参考 」这种前缀一起吃进去；所以先拿素材表里的名字去原文里 `find`，
  找不到的再用通用媒体后缀报一条「不认识的素材文件」，那种只报不改。
- **只报不改的占多数**。能机械修的只有三类，其余要么需要人判断（该不该绑这张图），
  要么需要模型（这句该怎么改）。

## 补丁

`backend/modules/prompts/patch.py`：

- 每个可修结论带一个字符区间 `fix(start, end, after)`；补丁就是这些区间的集合。
- 应用走 `rewrite.apply_spans`：倒序替换 + **反向还原校验**，校验不过就一个都不改。
- 重叠区间自动跳过并说明原因；越界区间也跳过（文本可能已经被改过）。
- 不做整段重写：整段重写看不出改了什么，也容易顺手改掉台词。

## 接口

| 方法与路径 | 说明 |
| --- | --- |
| `POST /api/prompts/segments/{seg}/check` | 诊断。不传 `content` 就诊断当前渲染结果，传了就诊断手里的草稿 |
| `POST /api/prompts/segments/{seg}/patch` | 生成补丁：`hunks`、`patched`、改前/改后的问题清单 |

返回同时带 `issues_before` 与 `issues_after`，前端据后者判断「修完还剩几条」，
不用自己再算一遍。

## 前端

右栏新增「检查」标签：

- 打开即检查当前草稿，报错条数直接标在标签上；
- 结论按 错误 / 提醒 / 建议 分级，带行号，可自动修的标「可自动修」；
- 「生成修复补丁」→ 逐条列出 `before → after` → 「应用到草稿」只改草稿，仍需手动保存；
- 应用后自动重跑诊断，问题数应当下降。

## 验收

后端 8 条用例（`tests/test_prompt_studio.py::TestChecks`）：

| 用例 | 判定 |
| --- | --- |
| 机械问题都查得出 | 时长 / 文件名 / 独白 / 缺小标题四类同时命中 |
| fixable 与 fix 一致 | 有 fix 才能标可修，区间合法 |
| 补丁修完问题消失 | 三类 fixable 改完后不再出现 |
| 只改选中的 code | 只传 `BODY_HAS_DURATION` 时，文件名那处不动 |
| 补丁可逆 | 按 hunk 反着换回去，逐字节回到原文 |
| 分镜表规则 | 镜数不一致、台词漏抄都能报 |
| 接口 | `/check` 有 summary，`/patch` 改后错误+提醒数下降 |
| 不传 content | `source=render` |

前端 9 条 UI 用例（新增 1 条：检查 → 生成补丁 → 应用到草稿）。

真后端实测：第 4 段渲染稿只剩 1 条 error ——「`@人物3` 不在素材表」，
这正是需要人去绑 Q 版小人图的那一条，属于该报的。

## 没做

- **模型那一半**：初稿 / 对话调整 / Provider 配置 / 暂存区文件 / `patches` 表。
  等配好 API Key 再上，届时复用本文的 patch 结构与 `apply_spans`。
- 补丁暂存与 24 小时过期（现在补丁只活在响应里，关掉页面就没了）。
- 只读工具集（`list_assets` / `get_shot`）。
