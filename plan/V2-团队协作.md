# V2 团队协作与局域网同步

依赖：P1 的资产索引与文件表、P2 的操作记录与文件操作、P8 的主分支。V2 分 C0–C4 五段，每段单独验收，前一段不通过不进入下一段。

## 目标

同一个安装包支持「本机模式」与「加入项目」。加入项目后，每人负责若干集，可以查看所有集的资产、分镜与提示词，只有负责人或被授权者能写某一集；文件改动通过局域网同步给其他人，媒体按需拉取。

## 进入条件

- P8 验收通过：`modules/` 分层稳定，`op_log` 带 `seq`、`prev_hash`、`op_hash`、`actor`，所有文件都有 `sha256`，路径为 POSIX 相对路径。
- `assets` 覆盖工作区全部文件，不只是素材。
- 两台 Windows 机器在同一网段，能互相访问监听端口。

## 范围

| 做 | 不做 |
| --- | --- |
| 项目链与集链、检查点 | 公链、代币、挖矿 |
| Ed25519 身份、一次性邀请 | 跨项目共享、公网穿透 |
| 集归属、转交、按范围授权与租约 | 独立中心服务器 |
| WS 操作同步与头部补缺 | 多人同时编辑同一段正文 |
| 内容寻址块、Range 传输、缓存配额 | CRDT 自动合并、媒体全量预取 |
| 分叉隔离与人工裁决 | 多签检查点（默认关闭） |
| 团队界面与网络诊断 | 八人以上的中继拓扑 |

## 步骤

### C0 身份与本地账本

1. 配置增加 `team` 段，默认关闭：`team.enabled=false`、`sync.listen_port=0`（系统分配）、`sync.cache_dir`、`sync.cache_limit_gb=50`。开启团队时生成密钥并写一条 `project.genesis`，关闭时保留全部表，只停用同步服务。

2. 身份：用 `cryptography` 生成 Ed25519 密钥对，私钥经 `keyring` 存 Windows 凭据管理器，条目名 `gachabench/<projectId>/<memberId>`。接口只返回公钥、成员 id 与密钥末四位，私钥不出本机。

3. 规范化哈希：所有操作先转成固定 JSON，再算 `sha256`。`signature` 不参与哈希，其余字段全部参与。`wallClock` 只用于显示。

```python
def canonical_json(obj) -> bytes:
    return json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False).encode("utf-8")

def op_hash(op: dict) -> str:
    body = {k: v for k, v in op.items() if k != "signature"}
    return hashlib.sha256(canonical_json(body)).hexdigest()
```

4. 追加操作：读链头，`seq = head.seq + 1`，`prevHash = head.hash`，`lamport = max(本地计数器, head.lamport) + 1`。插入与业务变更在同一事务内完成，`UNIQUE(chain_id, seq)` 兜住并发。任一链在同一时刻只有一个写者：项目链是发起人，集链是负责人或当前被授权人。

```python
def append(chain_id: str, type_: str, payload: dict, actor: str) -> Operation:
    head = repo.head(chain_id)
    op = {
        "chainId": chain_id,
        "seq": 0 if head is None else head.seq + 1,
        "prevHash": "0" * 64 if head is None else head.hash,
        "actor": actor,
        "lamport": max(clock.now(), 0 if head is None else head.lamport) + 1,
        "wallClock": utc_now_iso(),
        "type": type_,
        "payload": payload,
    }
    op["hash"] = op_hash(op)
    op["signature"] = identity.sign(op["hash"])
    repo.insert_op(op)
    return op
```

5. 本机文件写入的次序：先落盘并算哈希，再追加 `file.put`，最后广播。进程在两步之间崩溃时，`.gachabench/sync/pending.json` 留下待补记录，启动自检重新算哈希并补写操作，已存在同路径同哈希的操作则跳过。

6. 创世：新项目写 `project.genesis`，内容为项目 id、项目名、创建时间、发起人公钥。旧工作区第一次开启团队时，把当前文件表与现有 `op_log` 做成创世检查点，由发起人签名；`op_log` 的旧行留在原表，标注「v1 未签名历史」，不进入 `operations`。

7. 检查点：每 256 条操作写一条，内容为截至该 `seq` 的操作 Merkle 根、文件表 Merkle 根与签名。根的计算方式固定，任何节点对同一批操作得到同一结果。

```python
def checkpoint_roots(ops: list[Operation], files: list[tuple[str, str]]) -> tuple[str, str]:
    ops_root = merkle_root([op.hash for op in ops])
    files_root = merkle_root([sha256(f"{path}\0{digest}".encode()) for path, digest in sorted(files)])
    return ops_root, files_root
```

8. 启动自检：校验最近 100 条操作的签名与链接，核对文件表与磁盘，检查检查点根。不一致的链标记为 `SUSPECT`，暂停该链同步并在设置页列出差异，不自动修复。

9. 单机验收：同一操作重放两次得到同一哈希；改动 payload 一个字节，签名校验失败；从检查点恢复后链头一致；旧工作区开启团队后，文件表条目数与磁盘文件数一致。

### C1 操作同步

1. 传输：每个 sidecar 同时是 WS 服务端与客户端。服务端挂在 FastAPI 的 `/ws/peer`，客户端用现有 `uvicorn[standard]` 自带的 `websockets` 连接对端。消息为 JSON，单条不超过 64KB。

2. 握手五步，任一步超时 10 秒即断开：

| 步骤 | 方向 | 内容 | 校验 |
| --- | --- | --- | --- |
| `hello` | 双向 | 项目 id、成员 id、公钥、应用版本、监听端口 | 项目 id 一致，公钥在项目链中 |
| `challenge` | 接收方 → 发起方 | 32 字节随机数 | 一次性，5 分钟内有效 |
| `auth` | 发起方 → 接收方 | 对 `projectId + nonce + 对方公钥` 的签名 | Ed25519 验签 |
| `heads` | 双向 | 各链 `seq` 与 `hash` 的数组 | 链 id 对得上 |
| `ready` | 双向 | 进入正常消息流 | 无 |

应用版本不同时断开，`peers` 页显示「版本不一致」，不进入消息流。

3. 补缺优先于广播：握手完成后按 `heads` 比较，落后方发 `ops.since` 拉取，单批上限 500 条；缺口超过 1000 条时改取最近检查点，再从检查点之后补齐。之后每 30 秒交换一次头部，头部一致视为同步完成。

4. 广播：本地操作追加成功后推 `op.append`。收到方先校验签名、`prevHash`、`seq` 连续性与写者权限，通过后写入本地账本并更新文件表，再转发给尚未收到的节点。按 `opId` 去重，转发深度上限 3。

5. 远端 `file.put` 只带路径、哈希与大小，不带字节。落账后按 C2 的预取策略排队取块；块到齐后写工作区文件并更新 `assets`。尚未取到的媒体在资产列表标 `remote`，打开时再取。

6. 连接管理：对端表记录地址、端口、成员、最近握手结果与各链进度。断线重连退避为 1、2、5、10、30 秒，封顶 30 秒。手动地址保存在 `sync.peers`，mDNS 结果只作补充。

7. 发现：`zeroconf` 注册 `_gachabench._tcp`，TXT 记录带项目 id 与成员 id。发现列表过滤掉其他项目；手动地址优先于自动发现。

8. 双向验收：两个临时工作区各起一个 sidecar，回环 WS 连接。A 改第 2 集的一个文件，B 在 2 秒内看到新哈希与新内容；B 改第 3 集，A 同样看到。断开 5 分钟后重连，缺口按批补齐，重复操作不重复投影。

### C2 块同步

1. 块存储：文件按 1 MiB 切块，每块算 `sha256`，存 `.gachabench/blobs/<前两位>/<块哈希>`，相同块只存一份。`blobs` 行登记整文件：`hash` 为整文件 `sha256`，`chunks_json` 为块哈希数组，`size`、`chunk_size`、`chunk_count` 一并记录。`manifests` 负责路径到整文件哈希的映射。

2. 内容寻址的效果：提示词改一句，只产生一两个新块，其余块命中已有文件；同一段视频被两个集引用时只存一份。

3. 预取策略：

| 对象 | 行为 |
| --- | --- |
| 自己负责的集 | 全部文件即时拉取，包括视频 |
| 他人集 · md/json/txt/yaml | 即时拉取 |
| 他人集 · 缩略图 | 即时拉取，单张上限 256KB |
| 他人集 · 媒体 | 打开播放器或查看器时拉取，边下边播 |
| 项目公共资产 | 文字与缩略图即时，媒体按需 |

4. 取块接口：`GET /api/sync/blob/{hash}` 支持 `Range`。本机命中缓存直接返回；未命中时向持有该块的节点转发，按块对齐范围，逐块校验哈希，校验通过才写入缓存并返回字节。首块 256KB 到齐即可开始播放。

5. 续传：`sync_queue` 按 `peer_id`、`blob_hash`、`offset` 记录进度。进程重启后从最后一个完整块继续，不重传已校验部分。某个源连续两次块哈希不符，换下一个持有者；所有源都失败返回 `BLOB_HASH_MISMATCH` 并清掉坏块。

6. 缓存：默认上限 50GB，按最近最少使用淘汰。自己负责的集、正在播放的文件、最近 7 天打开过的文件不参与淘汰。缓存目录可在设置里改，换目录时校验块哈希后再登记。

7. 验收：改一句提示词只新增一个块；播放他人负责集的视频，开始播放前等待不超过 3 秒；传输中断后重启从断点续传；手工改坏一个块文件，取块时被发现并换源。

### C3 权限与界面

1. 加入项目：发起人生成一次性邀请，内容为项目 id、邀请 id、有效期（默认 7 天）。对方填入邀请，生成密钥并签 `member.join`；发起人在项目链上追加接纳操作。邀请用后失效，重复使用返回 `INVITE_INVALID`。

2. 集归属：`ep.assign` 指定集号与负责人，一集一行。转交写 `ep.transfer`，需要原负责人与新负责人双方签名，缺一方不生效。移交后新负责人立刻获得该集写权限，旧负责人的离线改动在提交时因 `prevHash` 不在主链被拒，本地保留为草稿。

3. 授权：写权限按租约发放，单次最长 24 小时。`grant.issue` 带被授权人、范围（`prompt`、`rename`、`delete`、`produce`）、到期时间、申请哈希与 nonce。租约期间负责人也不写这一集，界面显示「已借出，剩余 3 小时」；被授权人可以提前释放，负责人立刻恢复写入。

4. 申请：申请是请求人签名的消息，在对等节点间转发，落 `access_requests`，不写链。批准才写 `grant.issue`，里面带申请哈希。申请入口在只读提示条与设置页两处，范围默认只给 `prompt`，改名与删除需要单独勾选。

5. 收回：负责人广播 `grant.notice`，`action=revoke`，带授权 id 与签名。节点收到后立刻拒绝该被授权人的后续操作，即使对方不配合也写不进别人的副本。链上补记在租约结束或释放后完成，保持集链单写者。

6. 本地写入也要过权限：`policy.can_write(ep, member, now)` 返回 `owner`、`grantee` 或 `none`。`none` 时所有写接口返回 `UNAUTHORIZED_WRITE`（403），前端把编辑入口置灰并显示负责人。

7. 分叉处理：同一 `chainId` 下同 `seq` 出现不同哈希时，该集进入 `CHAIN_FORK`，暂停自动同步。两分支都保留，界面并排显示提交人、时间与文件差异，默认选中内容多的一支，但必须由负责人确认。确认后写一条 `fork.resolve`，另一支移入 `quarantine` 表，文件留在隔离目录，不做自动合并。

8. 界面：

- 设置页「团队」分区：本机身份、开启或离开团队、监听地址与端口、邀请生成、成员列表、集归属、待处理申请、有效授权、对端与缓存；
- 集页与段页顶部：负责人、当前写者、剩余租约；无权限时显示申请按钮；
- 资产页与审片台：他人集的写操作入口置灰，悬停说明原因，不隐藏内容；
- 底部任务条：在线成员、链头差异、待传块、缓存占用；
- 网络诊断：监听端口、防火墙提示、最近一次握手结果、到各对端的延迟。

9. 验收：未授权成员调用写接口返回 403；租约期间负责人写入返回 `LEASE_HELD`；授权到期后写接口立即拒绝；撤回后 1 秒内拒绝被授权人的写入；分叉时两分支都在，裁决后另一支进隔离区且链继续增长。

### C4 硬化

1. 限速与限额：每对端每秒不超过 50 条消息，单批不超过 500 条操作，单条不超过 64KB。超限先回 `error`，连续三次断开并 60 秒内不重连。块接口每秒最多 4 个并发范围请求。

2. 移除成员：发起人写 `member.remove`，所有节点停止与其握手，拒绝其后续操作，历史保留可查。对方本地数据不远程删除，设置页提示手动清理副本。

3. 诊断包：在 P8 诊断包基础上增加对端列表、各链头部、待传块数量、缓存占用、最近 200 条同步日志。不含私钥、不含正文与媒体。

4. 密钥备份：设置页导出加密文件，口令经 scrypt 派生密钥，AES-GCM 加密私钥与成员信息；恢复时校验 `member.join` 签名是否与项目链一致。发起人丢失密钥且没有备份时无法转交项目链写权，界面提前提示导出。

5. 传输加密：默认明文 WS 加签名，能看到内容但改不了。需要保密时用 `cryptography` 生成项目自签证书开 TLS，客户端按证书指纹校验，指纹随邀请分发。

6. 验收：断网、关机、重连、分叉四种情况下行为与 §12.6 的表一致；移除成员后其写入被拒；超速对端被断开；诊断包不含私钥；TLS 开启后指纹不符的连接被拒。

## 数据变更

v2 的迁移由 Alembic 单独一条 revision 完成，v1 表只加列不重建。`operations.op_id` 就是操作哈希，`blobs` 在 §12.7 的基础上增加 `chunks_json`，用来记录块顺序。

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `members` | id、pubkey、display_name、role、joined_at、status | 项目成员 |
| `member_devices` | id、member_id、pubkey、last_seen | 同一成员多台机器 |
| `episode_owners` | ep、owner_member_id、assigned_at、assigned_by | 一集一行 |
| `grants` | grant_id、ep、grantee、scopes_json、issued_at、expires_at、revoked_at、op_id | 授权凭证 |
| `access_requests` | id、ep、requester、scopes_json、reason、status、created_at、decided_at | 申请与决定 |
| `operations` | op_id、chain_id、seq、prev_hash、actor、lamport、wall_clock、type、payload_json、signature | 两级账本 |
| `checkpoints` | chain_id、seq、ops_root、files_root、signature、created_at | 每 256 条一个 |
| `blobs` | hash、size、chunk_size、chunk_count、chunks_json、created_at、last_seen_at | 块索引 |
| `manifests` | path、blob_hash、size、ep、owner_member_id、updated_at | 路径到文件 |
| `sync_state` | peer_id、chain_id、head_seq、head_hash、last_sync_at | 对端每链进度 |
| `sync_queue` | id、peer_id、blob_hash、offset、state、updated_at | 断点续传 |
| `quarantine` | op_id、chain_id、seq、reason、payload_json、moved_at | 分叉隔离区 |

唯一约束：`operations(chain_id, seq)`、`blobs(hash)`、`manifests(path)`、`episode_owners(ep)`、`members(pubkey)`。索引：`operations(chain_id, seq)`、`manifests(ep)`、`sync_queue(blob_hash, state)`。

对 v1 表的改动：

- `assets.sha256` 由 P1 的可空改为非空，迁移时对缺失哈希的文件补算；
- `assets.status` 增加取值 `remote`，表示文件在文件表中但字节尚未缓存；
- `segments.owner_member_id` 保留可空，v2 开启后由 `episode_owners` 回填；
- `op_log` 保留原表，不迁移到 `operations`，只作为未签名历史展示。

## 接口

WS 消息带统一外壳，`depth` 用于转发去重：

```json
{"v":1,"type":"op.append","msgId":"01J...","from":"<memberId>","depth":0,"body":{}}
```

握手与消息类型见 §12.8，实现时按同一张表落地。C0 只用到 `hello` 到 `ready` 的本地模拟；C1 接入 `op.append`、`op.batch`、`head.announce`、`presence`；C2 接入 `blob.announce`、`blob.need`；C3 接入 `grant.notice`；`error` 贯穿全程。

## 前端

- 团队入口只在设置页出现，不新增一级导航；未开启团队时整块置灰，只有「开启团队模式」一个按钮。
- 只读状态在页面层统一处理：路由加载时取一次 `myAccess(ep)`，为 `none` 时所有编辑控件进入禁用态，并在顶部显示负责人昵称与申请入口，不在每个按钮里重复判断。
- 状态查询用 TanStack Query，键为 `["sync","status"]` 与 `["team","peers"]`，30 秒轮询；WS 推送到达时直接写缓存，避免轮询与推送互相覆盖。
- 租约剩余时间每秒刷新，由前端本地倒计时，到期时重新取一次权限，不依赖本地时钟做权限判定。
- 分叉页面同时展示两分支的操作列表与文件差异，确认按钮二次确认，显示将被隔离的操作 id。

- 未开启团队时设置页只显示开关；

## v1 接缝

| 接缝 | v1 阶段 | v2 用法 |
| --- | --- | --- |
| 操作是唯一变更入口 | P1 起所有写操作落 `op_log`，带 `seq`、`prev_hash`、`op_hash`、`actor` | 升级为 `operations` 的追加入口 |
| 稳定标识 | P1 的 `assets.id`、P3 的 `segments.id` 不随路径变 | 改名不断链 |
| 内容哈希 | P1 扫描时写入 `sha256`，P2 改名后重算 | 判重与块传输 |
| 基础版本 | P2 的文件改动与 P4 的 patch 都带 `base_hash` | 冲突检测 |
| 路径规范 | P1 起统一 POSIX 相对路径 | 跨机器路径一致 |
| 资产即文件表 | P1 的 `assets` 覆盖工作区全部文件 | 同步范围不漏文件 |
| 所有者可空 | P3 的 `segments.owner_member_id` 可空 | 开启团队后按集回填 |
| 身份后置 | v1 不生成密钥 | 首次开启团队时生成并签创世 |

P1 与 P2 的实现里，这七项不达标就不要进入 V2，补做比改造便宜。

## 风险与回退

mDNS 被防火墙拦截是常态，手动地址与网络诊断必须在 C1 就可用，不能留到 C4。Windows 首次监听会弹授权，安装包首次启动时提前说明端口用途。

分叉裁决需要人理解两份分支的差别。界面给出文件差异、提交人与时间，默认选中内容多的一支，但保留另选。裁决前该集只读，其他集不受影响。

媒体缓存会撑大磁盘。配额、淘汰豁免与缓存目录可改三项在 C2 一起交付，不单独上线。

大文件首次同步慢。文字与结构先到，媒体边用边下；设置页显示每集的同步进度，避免用户以为卡住。

发起人密钥丢失无法再改项目归属。C4 提供加密备份与恢复，开启团队时提示导出一次。

回退方式：关闭 `team.enabled` 后回到单机模式，`sync` 服务不启动，`operations` 与 `blobs` 表保留不动，v1 页面照常读写。开启团队前先复制一份 `.gachabench` 目录，创世检查点写入后不回退到未签名状态。八人以上或需要公网时超出本方案范围，改为中继拓扑前先单独立项。
