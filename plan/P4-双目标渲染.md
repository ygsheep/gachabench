# P4 双目标渲染

依赖：P3 的中间层与绑定表。

## 目标

从同一份中间层渲染 Seedance 与 MiniMax H3 两套提示词，先把候选与当前文件做差异，再按区间写入。没有被选中的正文逐字保留，写入前跑一遍往返校验。

## 进入条件

- P3 能把样本段解析成 8 镜的中间层，绑定结果稳定。
- 已拿到两份真实提示词作为模板素材：一份 Seedance 成稿、一份 H3 成稿，确认两套的段落结构与标签体系。
- 确认 `<Picture N>`、`<Subject N>`、`<Audio N>` 的编号规则，渲染器与校验器共用同一份定义。

## 范围

| 做 | 不做 |
| --- | --- |
| 两套 Jinja2 模板与模板版本 | 不做自由文本生成 |
| 候选渲染、逐行差异 | 不做 Agent 改写（P5） |
| 按区间应用与快照 | 不做多目标同时写入 |
| 六条往返不变量 | 不做自动修复 |
| 正文只读查看与手动保存 | 不做协同编辑（v2） |

## 步骤

1. 加依赖 `jinja2`。模板放在 `backend/modules/prompts/templates/`：

```
templates/
├── seedance/v1.j2
├── seedance/v2.j2       后续版本按需增加
├── h3/v1.j2
└── shared/macros.j2
```

模板文件名与版本号写进 `render_profiles`，不写进 md 正文。PyInstaller 打包时用 `--collect-data` 带上整个 templates 目录。

2. 模板上下文只允许这些键：`segment`、`shots`、`materials`、`audio`、`settings`。渲染器用 `StrictUndefined`，模板引用不存在的字段直接报错，不输出空白。

3. 建 `backend/modules/prompts/render.py`：

- `build_context(segment_id)` 从中间层与绑定表组装；
- `render(target)` 返回完整候选字符串与 `template_version`；
- 目标不存在时返回 `TEMPLATE_MISSING`；
- 渲染是纯函数，不读文件、不发请求。

4. 候选返回前计算差异。用 `difflib.SequenceMatcher` 按行比对当前文件与候选，输出 `[{op, startLine, endLine, lines}]`，`op` 取 `equal`、`replace`、`insert`、`delete`。行号从 1 开始，与编辑器一致。

5. 应用时只替换用户勾选的 hunk。`POST apply-render` 的请求带 `baseHash` 与 `hunkIds`。服务端：

1) 比对当前文件哈希与 `baseHash`，不一致返回 `CANVAS_STALE` 或 `PATCH_CONFLICT`；
2) 把 hunk 映射回字符区间；区间必须落在 §①–§⑥ 或头部允许行内，越界返回 `PATCH_SCOPE`；
3) 按区间倒序替换，写前做反向还原校验；
4) 写临时文件并 `os.replace`；
5) 重新解析并跑六条不变量；
6) 生成快照，更新 `prompt_files.source_hash` 与 `segments.status`。

新目标还没有文件时，应用等于整篇写入，但仍要跑不变量。

6. 往返不变量：

| 不变量 | 判定 |
| --- | --- |
| 镜数 | 应用后 `[Shot N]` 数量与中间层一致 |
| 镜号集合 | `SHxxx` 集合不增不减不重排 |
| 标签集合 | `<Picture N>` 与 `<Subject N>` 编号集合与绑定表一致 |
| 围栏 | ```text 围栏数量与位置不变 |
| 段落 | §①–§⑥ 标题齐全且顺序不变 |
| 时长 | 各镜时长之和与目标时长偏差不超过 0.1s，超出只给警告 |

任一硬性项不通过，写回滚，原文件字节不变，返回差异位置。

7. 建表：

| 表 | 字段 |
| --- | --- |
| `prompt_files` | id、segment_id、target、path、source_hash、template_version、updated_at |
| `render_profiles` | id、target、template_name、template_version、variables_json、enabled |
| `snapshots` | id、segment_id、target、path、hash、created_at |

`prompt_files(segment_id, target)` 唯一。已有文件保留原名作为主目标，新目标按 `NN_段名_15s.<target>.md` 命名。

8. 接口：

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/segments/{seg}/render?target=` | 返回候选、差异、校验结果、模板版本 |
| `POST /api/segments/{seg}/apply-render` | 按 hunk 应用 |
| `GET /api/segments/{seg}/file?target=` | 取正文与哈希 |
| `PUT /api/segments/{seg}/file` | 保存手工编辑，服务端跑不变量 |
| `POST /api/segments/{seg}/validate` | 只跑校验 |

9. 前端：

- 段页顶部放目标切换（H3 为主，Seedance 为次），切换只改 URL 参数；
- 中栏用 CodeMirror 6，应用候选时切到 `@codemirror/merge` 双栏视图；
- 差异按 hunk 分组，右侧复选框控制是否应用，默认全选；
- 校验失败时在对应行打标记，底部列出未通过项；
- 保存按钮在 `dirty` 时才可用，保存后显示新哈希与快照时间。

## 数据变更

新增三张表。`segments.status` 增加 `rendered`、`dirty`、`conflict` 三个取值。

## 测试与验收

| 用例 | 判定 |
| --- | --- |
| 两目标渲染 | 同一中间层分别产出两套结构正确的候选 |
| 未选区域不变 | 只应用第 2 个 hunk，其余区域与原文件逐字节相同 |
| 镜数变化 | 中间层删一镜后渲染，校验报 `shotCount`，拒绝写入 |
| 标签重排 | 人为打乱 `<Picture N>`，校验报 `tagSet`，拒绝写入 |
| 模板缺失 | 返回 `TEMPLATE_MISSING`，前端提示导入模板 |
| 基准哈希过期 | 文件被外部改动后应用返回 `PATCH_CONFLICT` |
| 快照可读 | 应用后 `snapshots` 有记录，能取回应用前内容 |
| 大文本 | 40KB 正文渲染加差异在 1s 内完成（开发机实测） |

40KB 级真实样本数量尚不足，回归语料在 P4 开工前补充；样本不足时先用合成语料覆盖结构，不宣称覆盖真实写法。

## 风险与回退

模板与真实成稿的差距是最大风险。P4 先用 v1 模板对齐现有两份成稿，模板改动只影响候选，不影响已落盘文件。

手工编辑与渲染候选可能同时发生，靠 `baseHash` 拦住覆盖；两人同时改同一文件不在 v1 范围。

回退方式：P4 只新增表与接口，旧拆分台不受影响。停用渲染即可回到只读正文。
