# P7 制作任务台

依赖：P3 的中间层与绑定、P6 的 Take 结构。

## 目标

把跑片收成“提交任务”一件事。提交时冻结提示词、素材、参数与工作流版本，之后排队执行、可取消、可原样重试，产物自动进资产库与审片台。ComfyUI 仍是外部依赖，不可用时只影响这一段。

## 进入条件

- 现有 `comfy.py`、`generate.py`、`reconcile.py` 能连上一个可用的 ComfyUI 端点。
- 现有 `jobs` 表的字段与状态机可用；进程重启后把 `queued/running` 标为中断的逻辑已在 `main.py` 的启动扫尾里。
- P6 的块编号规则已确定。

## 范围

| 做 | 不做 |
| --- | --- |
| 任务快照与队列 | 不做工作流可视化编辑 |
| 提交、取消、重试 | 不做多机分布式跑片 |
| 产物回收与入库 | 不做模型下载与管理 |
| 端点与工作流健康检查 | 不做计费与配额 |

## 步骤

1. 建 `backend/modules/produce/`，把现有能力搬进来：

| 现有 | 新位置 | 处理 |
| --- | --- | --- |
| `comfy.py` 的 HTTP 客户端 | `modules/produce/client.py` | 原样搬入，补超时与取消 |
| `generate.py` 的提交逻辑 | `modules/produce/service.py` | 改为接收快照 |
| `reconcile.py` 的补收 | `modules/produce/ingest.py` | 保留周期补收 |
| 旧 `routers/generate.py` | 薄封装 | P8 删除 |

2. 快照内容：目标段与块、提示词正文全文、绑定素材列表（id 与文件名）、渲染目标、参数覆盖、工作流标识与版本、提交人、提交时间。快照存 `jobs.snapshot_json`，提交后不再变化。

3. 队列：进程内单队列，默认并发 1，可在设置里调到 2。任务状态 `queued`、`running`、`done`、`failed`、`canceled`、`interrupted`。同一段同一块已有排队任务时返回 `JOB_DUPLICATE`，请求可带 `force=true`。

4. 取消：排队中直接置 `canceled`；运行中先请求 ComfyUI 中断，再置 `canceled`，已生成的部分记为废稿。

5. 重试：读取原快照重新入队，不重新读当前提示词。界面上明确显示「按提交时的版本重跑」。

6. 产物入库：`ingest.py` 把产物写到工作区 `生成/` 下，命名 `第N集_第N段_第N块_takeN.mp4`，重名追加 `_02`。文件落盘后调 `assets` 的索引 upsert，再调 `review` 的卡片登记，两步同一事务的边界由 `assets` 先落盘、`review` 后写库。

7. 健康检查：`GET /api/health/comfy` 返回端点可达性、ffmpeg 版本、工作流映射是否完整。不可达时前端禁用提交按钮，排队任务保留，恢复后继续。

8. 接口：

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/jobs` | 参数 `status`、`seg`、`cursor` |
| `POST /api/jobs` | `{seg, block, target, params?, workflow?}` |
| `POST /api/jobs/{id}/cancel` | 取消 |
| `POST /api/jobs/{id}/retry` | 按快照重跑 |
| `GET /api/jobs/{id}` | 状态、日志尾部、快照摘要 |
| `GET /api/health/comfy` | 端点与工作流 |
| `GET /api/workflows` | 可用工作流与版本 |

9. 前端 `/produce`：

- 顶部模式与工作流选择，参数栏复用现有 `RunParamsBar` 的字段；
- 中栏队列，按状态分组，显示段、块、目标、提交人、耗时；
- 右栏任务详情：快照摘要、日志尾部、取消与重试；
- 提交入口同时出现在段页与审片台，带上当前段与块。

10. SSE 事件增加 `job.updated`，任务列表与顶部 `TaskBar` 共用同一份状态。

## 数据变更

`jobs` 补 `snapshot_json`、`workflow_version`、`target`、`submitter` 四列，全部可空；旧任务照常读取，快照为空时显示「旧任务，无法原样重跑」。

## 测试与验收

| 用例 | 判定 |
| --- | --- |
| 快照不可变 | 提交后改提示词，任务执行的请求体仍是旧正文 |
| 重试一致 | 同一任务重试两次，发往 ComfyUI 的请求体完全相同 |
| 重复提交 | 同段同块第二次提交返回 `JOB_DUPLICATE`，`force` 可覆盖 |
| 取消排队 | 状态立即变 `canceled`，不再发出请求 |
| 取消运行 | 调用中断接口后再置状态，产物不登记为卡片 |
| 重启扫尾 | 杀掉进程再启动，`running` 变 `interrupted` |
| 产物入库 | 完成后资产库出现文件，审片台出现对应 Take |
| 端点离线 | 返回 `COMFY_OFFLINE`，提交按钮禁用，队列保留 |
| 命名冲突 | 同名产物落到 `_02`，不覆盖旧 Take |

## 风险与回退

ComfyUI 的接口与工作流会变。客户端把提交与轮询分开，工作流版本写进快照；接口变更时旧快照任务标失败并提示，不猜测新接口。

进程内队列在崩溃时丢失执行中任务，这是已有行为。保留快照与产物补收，重启后用户可一键重试。

回退方式：旧 `generate` 路由保留到 P8，制作台出问题时可从段页回退提交；新列可空，旧页面不受影响。
