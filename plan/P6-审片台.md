# P6 审片台

依赖：P1 的媒体流与缩略图、P3 的镜结构与中间层。

## 目标

把卡片墙改成段、块、Take 三级浏览。播放头、镜号、提示词镜块三者对齐：点镜号能定位画面，播放到某镜时右栏高亮对应字段，两个 Take 能同步对比，也能单独放大看。

## 进入条件

- 现有 `cards` 表与 `_group_shots` 的 5s 分组规则可用，块编号口径与跑片一致。
- ffprobe 能读到至少一种真实成片的分辨率、帧率与时长。
- 采样一段真实视频，确认 WebView2 能播放其编码；不能播放的格式走外部打开或转码。

## 范围

| 做 | 不做 |
| --- | --- |
| 段、块、Take 树 | 不做时间线剪辑 |
| 计划边界到实际片长的映射 | 不做逐帧标注导出 |
| Video.js 播放、逐帧、区间循环 | 不做多轨音频 |
| 双联同步与单播切换 | 不做跨段对比 |
| 安全区与标记 | 不做自动质检 |

## 步骤

1. 建 `backend/modules/review/timeline.py`：

- 每个块的镜边界来自分镜时长；
- 成片实际时长来自 ffprobe；
- 按比例缩放：`actual / planned`；
- 每个镜的起止时间写成 `[{shot, start, end, plannedStart, plannedEnd}]`；
- 缩放比偏离 1 超过 10% 时返回 `scaled: true`，前端显示标记但不阻断。

2. 块与 Take 的读取复用现有 `cards` 表，补两列 `block_no`、`fps`（已有则跳过）。块编号按 `_group_shots` 的结果，与跑片提交时一致。

3. 接口：

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/segments/{seg}/takes` | 段内块与 Take 树，含每块计划时长与实际时长 |
| `GET /api/cards` | 参数 `seg`、`block`、`status`、`cursor` |
| `GET /api/cards/{id}` | 卡片详情与镜边界 |
| `PATCH /api/cards/{id}` | 正片、废稿、备注、拒收标签 |
| `POST /api/cards/{id}/export` | 单条或批量导出 |
| `GET /api/media?path=` | 复用 P1，支持 Range |
| `GET /api/cards/{id}/timeline` | 镜边界与缩放信息 |

4. 前端路由 `/review`：

- 左栏段列表，选中段后展开块；
- 中栏 Take 网格，支持双选进入对比；
- 右栏详情：时间码、镜号、提示词镜块、备注、标记按钮。

5. 播放器用 Video.js。封装 `VideoPane` 组件，暴露 `seek(time)`、`frameStep(dir)`、`loop(start, end)`。视频源走 `/api/media?path=`，浏览器直接请求，带 Range。

6. 双联同步：

- 主播放器为时钟源，副播放器只跟随 `seek` 与 `play/pause`；
- 主播放器 `timeupdate` 时若副播放器偏差超过 0.1s 才校正，避免抖动；
- 只保留主画面音频，副画面静音；
- 切换单播时销毁副实例，释放解码器。

7. 时间码联动：

- 播放头进入新镜时，右栏高亮对应行，并滚动到可见；
- 点击镜号或时间码发 `seek`，并把 `seg`、`block`、`take`、`t` 写进 URL；
- 从提示词页跳审片台只带 `seg` 与 `shot`，落地后定位到包含该镜的块；
- 镜号映射由后端给出，前端只做区间查找，不自己算时长。

8. 逐帧与循环：帧步进按 `fps` 换算秒数，`fps` 缺失时用 25 作为默认并提示。`I` 与 `O` 设区间起点与终点，`L` 开关循环。

9. 安全区：9:16 与 16:9 两套参考框，用 CSS 叠在视频上，可开关。参考框不写进视频文件。

10. 键盘：`J/K/L` 后退、暂停、前进，`←/→` 逐帧，`A/B` 切换对比，`Space` 播放暂停。编辑器聚焦时全部让位，只保留 `Esc`。

11. SSE 复用 P1 的 `/api/events`，新增 `card.updated`，列表与详情据此失效。

## 数据变更

`cards` 补 `block_no`、`fps` 两列（可空）；新增视图不需要新表。镜边界按需计算，不落盘，避免成片替换后边界过期。

## 测试与验收

| 用例 | 判定 |
| --- | --- |
| 边界映射 | 8 镜、计划 15s、实际 15.2s，边界按比例缩放且首尾对齐 |
| 缩放提示 | 实际 18s 时返回 `scaled: true` |
| 点击镜号 | 播放头落到该镜起点，误差不超过 1 帧 |
| 双联同步 | 连续播放 30s，副画面偏差不超过 0.1s |
| 单播切换 | 关闭对比后只剩一个解码实例，内存下降 |
| 逐帧 | 连续按 10 次前进，时间码前进 10 帧 |
| 区间循环 | 只在设定区间内循环，越界即回起点 |
| URL 还原 | 刷新后段、块、Take、时间码都恢复 |
| 编码不支持 | 返回 `MEDIA_UNSUPPORTED`，提供外部打开与转码 |
| 端到端 | Playwright 用 5 秒样片跑通打开、播放、跳镜、对比 |

## 风险与回退

WebView2 的解码能力取决于系统组件，H.265 与部分 10bit 文件可能无法播放。这一段先做 H.264 样片，其他格式给两条退路：外部播放器打开、用 ffmpeg 转成临时 H.264 预览。

双联同步容易抖动，校正阈值设为 0.1s，低于阈值不打断播放。

回退方式：保留旧 `GachaBoard` 路由，审片台出问题时可切回卡片墙；新增列可空，不影响旧页面。
