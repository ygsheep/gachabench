# P3 第一刀：三段式渲染与「拆分台」归位

依赖：P1（资产索引）、P2（文件操作）。对应 [P3-分镜解析与中间层](../P3-分镜解析与中间层.md) 的第 2、3 步与第 8 步前端部分，但把 P4 的「Seedance 输出」提前做了一半——只做 Seedance 一个目标，H3 仍是旧链路。

## 为什么要先做这一刀

分镜表已经写得很细（21 字段、道具追踪、风险登记），但落到提示词还得人肉抄一遍：抄风格、抄场景、抄台词、数发声处数。抄错一次，跑片就飞一次。三段式模板把这个动作固定成了格式，正好可以用代码把「抄」这一步替掉。

同时拆分台一直占着一级入口，但它只是「出片前把 15s 切成 3 块」。P3 起它收进「制作」，一级导航只剩三段主线：提示词工程（写） → 制作（跑） → 审片台（看）。

## 渲染规则（照模板硬规矩）

1. 台词一字不改；内心独白标「无口型，是画外音」。
2. 素材表映射「占位 ↔ 文件名」，正文只用占位，不写真实文件名。
3. 景别缩写展开成中文（MCU → 中近景），英文只留在分镜表里。
4. 正文不写时长；时长进「分镜时间动作表」。
5. 尾部防崩约束按分镜表自己的风险登记生成，一条只堵一个失败点。
6. 风格与场景默认继承项目里最近一份提示词，避免每段重打、也避免各段风格漂移。

## 素材绑定（人工改绑）

自动匹配只能覆盖「文件名里写着人名」的情况。Q 版小人、通用道具、备用音色这些
自动配不上的，必须能人工指定，否则每段都留一个空占位。

- 绑定只存「人改过的」：表 `prompt_bindings` 键为（`segment_id`, `placeholder`），
  值存工作区相对路径。自动匹配不进库，重新解析分镜表不会把人的判断冲掉。
- 三种状态：`manual`（手动指定）/ `ignored`（忽略，编号保留不回收）/ `auto`（自动）。
  界面上点「恢复自动」= 删记录。
- 被忽略的占位仍参与编号，也仍写在正文里，但**不进素材表**、不算 issue。
- 素材表只列真有文件的占位：它是上传清单，列一堆「待指定」只会让人以为漏了东西。
- 指定文件只能在工作区内：`../`、盘符外路径一律 400。

## 验收

后端 17 条用例（`backend/tests/test_prompt_studio.py`）：

| 用例 | 判定 |
| --- | --- |
| 21 字段解析 | 3 镜、15.0s、镜号 / 起始时间正确 |
| 三种台词体例 | `说：“…”` 有口型、`内心独白：…` 无口型、`【内心】名：…` 无口型 |
| 缺列 | `PARTIAL` + `MISSING_COLUMN`，其余列照读 |
| 无表 | `NO_TABLE`，不抛错 |
| 重复镜号 | 进 issues，不静默合并 |
| 时长偏差 | 超 0.1s 给 `DURATION_DRIFT`，不阻断 |
| 素材绑定 | 名字 + 用途词加权，睡衣段不拿到 Q 版图 |
| 正文只用占位 | 前缀里不出现真实文件名 |
| 未绑定 | `MATERIAL_UNBOUND` 并留空 |
| 渲染确定性 | 同输入两次输出逐字节相同 |
| 落盘 | 撞名 409，确认后覆盖；`../` 文件名 400 |
| 继承 | 从旧提示词取到风格、场景与年代地域 |
| 手动指定 | 覆盖自动结果，`source=manual`，素材表改用新文件 |
| 忽略 | `source=ignored`，不进素材表、不报 issue，编号不回收 |
| 恢复自动 | 删记录后回到自动匹配的那张图 |
| 越界路径 | `../../etc/passwd` → 400 |
| 候选清单 | `kind=audio` 只回音频，`q` 能过滤 |

前端：`tsc -b`、`oxlint`（新增文件 0 warning）、`vitest` 5 条三栏用例通过；并用真后端做过一次端到端冒烟（段列表 → 镜表 → 【风格】→ 素材表）。
