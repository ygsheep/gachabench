# P3 分镜解析与中间层

依赖：P1（资产记录）、P2（按 id 绑定的引用）。

## 目标

把分镜表的 21 字段读成结构化中间层，把每镜的素材编号绑到资产库里的具体文件。解析不完整时给出缺什么，而不是整段报错。

## 进入条件

- 手上有至少一份真实分镜样本，格式为 21 字段表加 §④ 代码块。样本 `分镜脚本_第12集第4段15s.md` 有 8 镜、总时长 15.0s、镜号 `SC12-SH401` 到 `SC12-SH408`。
- 现有 `splitter.py` 与 `prompt_locator.py` 的 229 个用例仍通过，搬到新模块后行为不变。

## 范围

| 做 | 不做 |
| --- | --- |
| 21 字段表解析、抬头解析 | 不做渲染（P4） |
| 中间层存取与哈希 | 不做正文编辑 |
| 素材自动绑定、待绑定、忽略 | 不做 Agent（P5） |
| 段列表与三栏骨架 | 不做播放器（P6） |
| 部分解析与问题列表 | 不改分镜源文件 |

## 步骤

1. 建 `backend/modules/prompts/`，把现有文本能力搬进来：

| 现有 | 新位置 | 处理 |
| --- | --- | --- |
| `splitter.py` 的代码块与镜块解析 | `modules/prompts/parse.py` | 函数原样搬入 |
| `prompt_locator.py` 的标签定位 | `modules/prompts/locate.py` | 函数原样搬入 |
| `splitter.py` 的拆分逻辑 | `modules/prompts/split.py` | 暂不修改 |
| 旧 `splitter.py`、`prompt_locator.py` | 薄封装，转调新模块 | 旧路由继续可用，P8 删除 |

搬迁时同步迁移对应用例，保证同一份输入得到同一份输出。

2. 分镜表解析：

- 从文件名提取集号与段号，例如 `第12集第4段15s` 得到 `(12, 4, 15.0)`；
- 找 21 字段表头，按列名建映射，不按列序猜；
- 读每一行，镜号列取 `SH` 后的三位数字，`401` 归一到镜序 1；
- 时长列去掉 `s` 转浮点；
- 素材列按顿号、逗号、空格切分，保留原始编号文本；
- 总时长以各镜时长求和为准，抬头值只用来比对。

3. 列缺失处理：必需列为镜号、时长、景别、画面内容、素材编号。缺任一列返回 `PARSE_PARTIAL`，`issues` 里给出缺失列名与该列影响的行数。缺表时返回 `NO_TABLE`，界面显示「未找到 21 字段表」，仍允许手工填。

4. 中间层结构存 `canvas_json`，字段：

| 区块 | 内容 |
| --- | --- |
| `segment` | 集、段、目标时长、画幅、帧率、风格、源文件路径 |
| `shots` | 镜序、镜号原文、景别、摄法、机位、运镜、焦段、时长、画面、动作、台词、音效、转场、光线、色彩、道具、服装、特效、节拍、风险、素材 |
| `materials` | 编号、文件名、绑定的 asset_id、状态 |
| `audio` | 台词段与音效映射，P4 再补 `<Audio N>` |
| `issues` | 缺失列、重复镜号、时长偏差、未绑定素材 |

中间层哈希 `canvas_hash` 对规范化 JSON 计算，键排序、无空白。源文件哈希变化时把中间层标 `stale`，不自动覆盖用户改过的字段。

5. 建表：

| 表 | 字段 |
| --- | --- |
| `segments` | id、ep、no、storyboard_path、duration_target、status、canvas_hash、canvas_json、source_hash、updated_at |
| `shots` | id、segment_id、no、duration、framing、camera、movement、payload_json |
| `bindings` | id、segment_id、shot_no、tag_kind、tag_no、asset_id、source、ignored |

`segments(ep, no)` 唯一，`shots(segment_id, no)` 唯一。`bindings` 的 `tag_kind` 在 P3 只有 `material`，P4 增加 `Picture`、`Subject`、`Audio`。

6. 绑定规则：

1) 素材文件名与 `assets.path` 的文件名完全相等，直接绑定；
2) 否则按主体匹配：文件名第一段等于资产 `subject`，且剩余部分包含用途词（四视图、表情、场景、道具），命中多个时进待绑定；
3) 仍无结果则待绑定，界面列出候选（同主体的资产按相似度排序）；
4) 用户选择后写 `bindings.source="manual"`；
5) 忽略某项写 `ignored=true`，编号保留不回收。

绑定用 `asset_id`，不用路径。P2 改名后绑定自动跟着 id 走。

7. 接口：

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/segments` | 参数 `ep`、`status`、`q`，返回段、镜数、时长、状态 |
| `POST /api/segments/{seg}/parse` | 解析指定段，`seg` 为两位段号，可带 `ep` |
| `GET /api/segments/{seg}/canvas` | 中间层与 `issues` |
| `PUT /api/segments/{seg}/canvas` | 保存字段修改，重算哈希，标 `dirty` |
| `PUT /api/segments/{seg}/bindings` | 手动绑定或忽略，参数为镜序与素材编号数组 |

8. 前端：

- `/prompts` 段列表：集号分组、段号、镜数、时长、状态（未解析、部分解析、已就绪、待绑定）；
- `/prompts/$seg` 三栏：左栏 21 字段表（TanStack Table，列可折叠），中栏画面与台词详情，右栏素材与绑定；
- 缺列时顶部黄条列出缺失项，表格照常显示能读到的列；
- 待绑定素材用红点标在镜行与右栏，支持搜索资产与一键忽略；
- 一切修改先落中间层，不碰 md 正文，页面上明确标「尚未写入提示词」。

## 数据变更

新增 `segments`、`shots`、`bindings` 三张表。`segments.canvas_json` 是中间层的持久化位置，md 正文不在这一段写。

## 测试与验收

| 用例 | 判定 |
| --- | --- |
| 真实样本解析 | 8 镜、15.0s、每镜 21 字段齐全，镜号 401 到 408 |
| 重复镜号 | `issues` 列出重复项，不静默覆盖 |
| 缺素材列 | 返回 `PARSE_PARTIAL`，其余字段仍可读 |
| 缺表 | 返回 `NO_TABLE`，界面可手工补 |
| 时长偏差 | 各镜之和与抬头差超过 0.1s 时给警告，不阻断 |
| 自动绑定 | 文件名完全相等的素材全部绑定成功 |
| 改名后绑定 | P2 改名资产后，绑定仍指向同一 asset_id |
| 忽略不回收 | 忽略第 2 项后新增第 3 项，编号仍是 3 |
| 中间层哈希 | 同样内容两次保存哈希相同 |

## 风险与回退

分镜表格式可能有变体，例如列名带空格、镜号位数不同、表头多一列。解析按列名匹配并对未知列忽略，不把未知列当错误。

中间层只是缓存，md 仍是真相。解析出错时删掉该段记录重跑即可，不影响工作区文件。

回退方式：旧 `splitter.py` 与新模块并存，旧拆分台继续工作；关闭段接口即可退回 P2 状态。
